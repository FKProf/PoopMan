# Test Failures due possible code bugs

## PoopMan.UnitTests.csproj - Update_WhenEnterPressedOnItem0_StopsTitleAudioAndChangesToGameScene
- **Confidence**: High
- **Test File**: PoopMan.UnitTests\Scenes\TitleSceneTests.cs
- **Bug Location**: PoopMan\Scenes\TitleScene.cs@1

### Analysis
The test file header explicitly documents that TitleScene and all its Scene subclasses depend on MonoGame's static Core singleton (Core.ContentManager, Core.GraphicsDevice, Core.Input). There is no interface, virtual property, or dependency-injection point that would allow substituting test doubles for these static members. The test body is intentionally empty because the test cannot be implemented without crashing the test host. The fix requires adding abstraction seams to the production code so that the MonoGame static dependencies can be mocked or replaced in tests. Until that is done, the test cannot be made runnable.

### Suggested Fix
To make TitleScene testable, the production code needs to introduce abstraction seams over the MonoGame static singletons. The recommended approach is:

1. Define interfaces such as `IContentManager`, `IInputManager`, and `IAudioManager` that wrap the MonoGame static calls.
2. Inject these interfaces into `TitleScene` via constructor parameters (dependency injection).
3. In production, pass the real MonoGame-backed implementations; in tests, pass Moq mocks.

For example, the `TitleScene` constructor could change from relying on `Core.ContentManager` directly to accepting an `IContentManager contentManager` parameter:

```csharp
public TitleScene(IContentManager contentManager, IAudioManager audioManager, IInputManager input)
{
    // use injected dependencies instead of Core.* statics
}
```

Alternatively, a lighter-weight approach is to introduce a static `CoreAccessor` abstraction with a replaceable delegate/factory so tests can swap in headless stubs without a full DI refactor. Until one of these seams exists, the test host will crash whenever `TitleScene` is instantiated.
